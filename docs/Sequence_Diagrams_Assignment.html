System Architecture Overview

The CSE Routine Generator handles complex multi-constraint scheduling (preventing teacher overlaps, room collisions, and lab slot packing) using backtracking heuristics with rapid restarts. The sequence diagrams below detail key workflows across the presentation, application, and persistence layers.

1. Authentication & Security

Role-based access control with secure credential validation and session token issuance.

2. Excel Ingestion & Validation

Multi-sheet parsing (teachers, courses, rooms) with strict relational consistency checks.

3. Constraint Scheduling & AI Diagnostics

Bin-packing backtracking solver with OpenRouter AI bottleneck advisor on deadlocks.

4. Interactive Editing & PDF Export

Real-time conflict detection during manual adjustments and server-side PDF compilation.

1. User Authentication Flow (Login Sequence)
Demonstrates the authentication life cycle: frontend credential dispatch, password hash verification via MySQL, and secure session establishment. 
sequenceDiagram
    autonumber
    actor User as User (Admin)
    participant Client as Frontend (React)
    participant AuthRoute as Auth Route (/api/auth)
    participant DB as MySQL Database

    User->>Client: Enter Email & Password, click "Login"
    Client->>AuthRoute: POST /api/auth/login {email, password}
    AuthRoute->>DB: SELECT * FROM users WHERE email = ?
    DB-->>AuthRoute: User Record (Hashed Password, Role)

    alt Invalid Credentials
        AuthRoute-->>Client: 401 Unauthorized {message: "Invalid credentials"}
        Client-->>User: Display error message
    else Valid Credentials
        AuthRoute->>AuthRoute: Verify bcrypt hash & generate JWT/Session
        AuthRoute-->>Client: 200 OK {token, user: {id, name, role}}
        Client->>Client: Store token in storage & initialize state
        Client-->>User: Redirect to Dashboard / Homepage
    end
Step Source & Target Description & Technical Context
1 - 2 User → Client → Auth API User submits authentication form. React executes asynchronous fetch to /api/auth/login.
3 - 4 Auth API ↔ MySQL Database Server looks up user by email and retrieves salt/hashed password.
5 - 8 Auth API → Client → User If verified, returns JSON response with auth token; Client persists state and routes user to dashboard.
2. Excel File Upload & Validation Flow
Details the extraction and validation pipeline for multi-tab Excel sheets containing courses, teachers, and rooms before database persistence. 
sequenceDiagram
    autonumber
    actor User as Admin
    participant Client as Frontend (React UI)
    participant UploadRoute as Upload Route (/api/upload)
    participant Parser as ExcelParser Service
    participant Validator as Validators Service
    participant DB as MySQL Database

    User->>Client: Selects & uploads Excel file (.xlsx)
    Client->>UploadRoute: POST /api/upload (multipart/form-data)
    UploadRoute->>Parser: parseExcel(fileBuffer)
    Parser-->>UploadRoute: Structured Data (Teachers, Rooms, Courses)
    
    UploadRoute->>Validator: validateUploadedData(parsedData)
    
    alt Validation Failed (Missing fields / Format error)
        Validator-->>UploadRoute: Validation Error Array
        UploadRoute-->>Client: 400 Bad Request {errors}
        Client-->>User: Render error alerts & corrective hints
    else Validation Passed
        Validator-->>UploadRoute: Validated Dataset
        UploadRoute->>DB: INSERT INTO batches & raw_data
        DB-->>UploadRoute: batchId & confirmation
        UploadRoute-->>Client: 200 OK {batchId, message: "Upload Successful"}
        Client-->>User: Show success banner & enable "Generate Routine"
    end
Step Components Description & Technical Context
1 - 2 User → Client → Upload API User selects departmental dataset. Express Multer middleware intercepts binary payload.
3 - 4 Upload API ↔ ExcelParser Parses sheets into structured JSON objects (Teacher loads, Lab/Theory rooms, Batches).
5 - 8 Validator ↔ MySQL → Client Verifies room capacities and credit counts; writes raw dataset into batches table.
3. Automated Routine Generation & AI Diagnostics Flow
The core mathematical engine: Backtracking with bin-packing constraints, randomized restarts, and automated OpenRouter AI advisor fallback. 
sequenceDiagram
    autonumber
    actor User as Admin
    participant Client as Frontend (React)
    participant SchedRoute as Schedule Route (/api/schedule)
    participant Scheduler as Scheduler Engine
    participant Diagnostics as Diagnostics Service
    participant OpenRouter as OpenRouter AI API
    participant DB as MySQL Database

    User->>Client: Click "Generate Routine" for Batch
    Client->>SchedRoute: POST /api/schedule/:batchId
    SchedRoute->>DB: SELECT courses, teachers, rooms WHERE batch_id = ?
    DB-->>SchedRoute: Batch Records
    
    SchedRoute->>Scheduler: generateSchedule(dataset, constraints)
    
    note over Scheduler: Backtracking + Bin Packing + Rapid Restarts

    alt Feasible Schedule Found
        Scheduler-->>SchedRoute: Generated Routine Slots
        SchedRoute->>DB: INSERT INTO class_routines (batch_id, slots)
        DB-->>SchedRoute: Persistence OK
        SchedRoute-->>Client: 200 OK {routineGrid, stats}
        Client-->>User: Render Interactive Timetable Grid
    else Infeasible Schedule (Deadlock / Resource Shortage)
        Scheduler-->>SchedRoute: Failure (Unscheduled courses & conflicts)
        SchedRoute->>Diagnostics: analyzeBottlenecks(conflicts, dataset)
        Diagnostics->>OpenRouter: POST /chat/completions (Bottleneck context)
        OpenRouter-->>Diagnostics: AI Advisory & Fix Instructions
        Diagnostics-->>SchedRoute: Diagnostic Report + AI Recommendations
        SchedRoute-->>Client: 422 Unprocessable Entity {diagnostics, aiAdvice}
        Client-->>User: Display AI Advisor Drawer with resolution steps
    end
Heuristic Note: The scheduler guarantees zero double-booking for instructors, enforces room-type affinities (Theory vs Lab), and isolates 3-hour lab periods in morning blocks using bin-packing.
4. Interactive Routine Modification & Conflict Validation Flow
Handles live timetable editing via drag-and-drop or modal updates with real-time atomic conflict detection across all departmental batches. 
sequenceDiagram
    autonumber
    actor User as Admin
    participant Client as Frontend (Timetable Grid)
    participant EditRoute as Edit Route (/api/edit)
    participant Validator as Conflict Validator
    participant DB as MySQL Database

    User->>Client: Moves / edits slot (Change Day, Time or Room)
    Client->>EditRoute: PUT /api/edit/:routineId {day, slot, roomId, teacherId}
    
    EditRoute->>Validator: validateSlotAvailability(batchId, day, slot, roomId, teacherId)
    Validator->>DB: SELECT * FROM class_routines WHERE day=? AND slot=? AND (room_id=? OR teacher_id=?)
    DB-->>Validator: Conflicting Slots (if any)
    
    alt Conflict Detected (Double-booked teacher or room)
        Validator-->>EditRoute: Conflict details (e.g. "Room 402 occupied by Batch 21")
        EditRoute-->>Client: 409 Conflict {message, conflictInfo}
        Client-->>User: Rollback UI change & show warning notification
    else No Conflict Found
        Validator-->>EditRoute: Slot Available
        EditRoute->>DB: UPDATE class_routines SET day=?, slot=?, room_id=? WHERE id=?
        DB-->>EditRoute: Update Success
        EditRoute-->>Client: 200 OK {updatedRoutine}
        Client-->>User: Update Grid UI smoothly
    end
Step Components Description & Technical Context
1 - 2 User → Client → Edit API Administrator reassigns a period. UI triggers optimistic update and dispatches PUT payload.
3 - 4 Edit API ↔ Validator ↔ DB Verifies cross-batch integrity to ensure neither instructor nor classroom is double-booked.
5 - 8 Edit API → Client → User On collision: rejects with 409 and rolls back state. On success: commits update to DB.
5. Routine PDF Export Flow
Transforms the finalized schedule into a publication-ready departmental routine document with unified university headers and teacher legends. 
sequenceDiagram
    autonumber
    actor User as Faculty / Student
    participant Client as Frontend (React UI)
    participant ExportRoute as Export Route (/api/export)
    participant PdfGen as PdfGenerator Service
    participant DB as MySQL Database

    User->>Client: Clicks "Download PDF"
    Client->>ExportRoute: GET /api/export/pdf/:batchId
    ExportRoute->>DB: Fetch complete routine grid & teacher lookup table
    DB-->>ExportRoute: Routine Schedule Records
    
    ExportRoute->>PdfGen: generatePdf(routineData)
    PdfGen->>PdfGen: Build structured document (Headers, Grid, Legend)
    PdfGen-->>ExportRoute: Binary PDF Buffer (application/pdf)
    
    ExportRoute-->>Client: 200 OK (Content-Type: application/pdf)
    Client->>Client: Generate Blob URL & trigger download
    Client-->>User: Save publication-ready PDF file
Step Components Description & Technical Context
1 - 3 User → Client → Export API → DB Client requests binary export. Server aggregates routine, room names, and teacher initial legends.
4 - 5 Export API ↔ PdfGenerator Generates formatted landscape table mirroring the React RoutineGrid layout.
6 - 8 Export API → Client → User Streams PDF buffer with Content-Disposition: attachment for immediate download.
